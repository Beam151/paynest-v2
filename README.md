# ระบบจัดการร้าน (PayNest v2)

ระบบเรียกเก็บส่วนต่างจากยอดขายของร้านในเครือ เก็บเป็น **รอบครึ่งเดือน**
มีหน้าเว็บหลังบ้านสำหรับ 3 บทบาท (ส่วนกลาง · ร้านค้า · เซล) และแจ้งเตือนผ่าน Telegram

รุ่นนี้พอร์ตจากระบบเดิม (Node.js + SQLite) มาเป็น **CodeIgniter 4 + MySQL/MariaDB**
หน้าเว็บ, API, กติกาธุรกิจ และข้อความทุกคำเหมือนเดิม · ชุดทดสอบของระบบเดิมทั้งสองชุดรันกับรุ่นนี้ผ่านครบ

- PHP ≥ 8.2 + CodeIgniter 4.7
- MariaDB 10.4+ หรือ MySQL 8.0.16+ (ทดสอบแล้วบน MariaDB 10.4)
- หน้าเว็บเป็น vanilla JS + ES modules — **ไม่มีขั้นตอน build** อยู่ใน `public/`
- งานเบื้องหลัง (Telegram, เตือนร้าน, สำรองข้อมูล) ให้ cron เรียกทุกนาที: `php spark schedule:run`
- ตั้งค่าแค่การต่อฐานข้อมูล — กุญแจลับและรหัสแอดมินคนแรกระบบสุ่มให้เอง

## เริ่มใช้งานในเครื่อง

ต้องมี PHP 8.2+ (ส่วนขยาย intl, mbstring, mysqli, curl, gd, openssl, zlib — XAMPP มีครบ) · Composer · MySQL/MariaDB

```bash
composer install
cp env .env                       # แก้ 2 เรื่อง: CI_ENVIRONMENT = development และค่าฐานข้อมูล (database.default.*)
mysql -u root -e "CREATE DATABASE paynest CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
php spark migrate                 # สร้างตาราง
php spark db:seed DemoSeeder      # บัญชี + ข้อมูลตัวอย่าง (เซิร์ฟเวอร์จริงไม่ยอมรัน)
php spark serve                   # เปิด http://localhost:8080
```

ข้อความ Telegram ที่เกิดจากการกดในหน้าเว็บ ระบบส่งให้ทันทีหลังตอบคำขอ
แต่งานตามเวลา (สรุปรายวัน, เตือนร้าน, อ่านข้อความถึงบอทตอนร้านผูก Telegram, สำรองข้อมูล) ไม่รันเองในเครื่อง dev —
อยากลองให้เปิดอีกหน้าต่างแล้วรัน `php spark schedule:work`

บัญชีตัวอย่างหลัง `db:seed` (ใช้ในเครื่อง dev เท่านั้น — เซิร์ฟเวอร์จริงไม่ยอมใช้รหัสพวกนี้):

| บทบาท | ผู้ใช้ | รหัสผ่าน |
| --- | --- | --- |
| ส่วนกลาง (super admin) | `superadmin` | `admin1234` |
| เจ้าของร้าน | `bkk01` / `cnx01` … (10 ร้าน) | `franchise1234` |
| ผู้ช่วยร้าน | `bkk01-staff` | `staff123456` |
| เซล | `sale01` … `sale04` | `sale1234567` |

> `CI_ENVIRONMENT = development` = โหมดทดสอบ: ไม่บังคับ Google Authenticator · `production` = เซิร์ฟเวอร์จริง: บังคับทุกบัญชีส่วนกลาง (ปิดได้ด้วย `paynest.enforceAdmin2fa = false` ใน `.env` — ไม่แนะนำ)
> ถ้ารัน `php spark app:install` ก่อน `db:seed` แอดมินจะได้รหัสสุ่มแทน `admin1234` — อยู่ในไฟล์ `writable/data/initial-admin-password.txt`

### คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
| --- | --- |
| `php spark serve` | เซิร์ฟเวอร์สำหรับพัฒนา (เครื่องจริงใช้ nginx/Apache + PHP-FPM — ดู DEPLOY.md) |
| `php spark app:install` | ติดตั้ง/อัปเดต: migration + กุญแจลับ + แอดมินคนแรก · รันซ้ำได้ทุกครั้งหลัง `git pull` ไม่ล้างข้อมูล |
| `php spark schedule:run` | งานตั้งเวลา — ให้ cron เรียกทุกนาที |
| `php spark schedule:work` | งานตั้งเวลาแบบรันค้างไว้ (แทน cron · ร้านผูก Telegram เสร็จใน 10 วินาทีแทนไม่เกิน 1 นาที) |
| `php spark app:backup` | สำรองข้อมูลทันที (ปกติระบบทำเองทุกคืน ตี 3 ครึ่ง) |
| `php spark migrate` | รัน migration ที่ค้าง (`app:install` ทำให้อยู่แล้ว) |
| `php spark db:seed DemoSeeder` | ใส่ข้อมูลตัวอย่าง — dev เท่านั้น |
| `php spark app:reset` | ลบตารางทั้งหมด — dev เท่านั้น · มีบิลอยู่ต้องใส่ `--yes-delete-everything` · สำรองให้ก่อนลบเสมอ |
| `php spark 2fa:reset <username>` | ปลด Google Authenticator ของผู้ใช้ (กรณีทำมือถือหาย และไม่มีแอดมินอื่น) |
| `composer test` · `composer test:smoke` · `composer test:pentest` | ทดสอบทั้งหมด / ฟีเจอร์ / เจาะระบบ — ใช้ฐานข้อมูลแยก ไม่แตะข้อมูลจริง (ดู tests/README.md) |
| `node tools/build-icons.mjs` | สร้าง `public/icons.svg` ใหม่ (เฉพาะตอนเพิ่มไอคอน — ดู HANDOVER.md) |

## บทบาทในระบบ

| | ส่วนกลาง | เจ้าของร้าน | ผู้ช่วยร้าน | เซล |
| --- | --- | --- | --- | --- |
| กรอกยอดขาย · ออกบิล · ตรวจสลิป | ✓ | ✗ | ✗ | ✗ |
| หน้าแรก | งานที่ต้องทำวันนี้ + ภาพรวมทุกร้าน | รอบนี้ร้านได้เท่าไร · อันดับ · แนวโน้ม · บิล | ตามสิทธิ์ | รายได้ค่าคอม |
| ดูบิล / แจ้งชำระ | ทุกร้าน | ของร้านตัวเอง | ตามสิทธิ์ที่เจ้าของให้ | ✗ |
| จัดการผู้ช่วย | ซัพพอร์ต (ตั้งรหัส/ระงับ) | ✓ เพิ่ม + เลือกสิทธิ์ | ✗ | ✗ |
| ประกาศถึงร้าน · ตั้งค่าแจ้งเตือน · บัญชีรับเงิน | ✓ | อ่านประกาศ · เลือกแจ้งเตือนของตัวเอง | อ่านประกาศ | ✗ |

สิทธิ์ของผู้ช่วยเลือกได้ 4 ข้อ: `bills` ดูบิล · `pay` แจ้งชำระ · `reports` ดูรายงาน · `products` ดูสินค้า
ส่วนกลางกด **👁 ดูมุมมองนี้** เพื่อดูระบบแบบที่ร้าน/เซลเห็นได้ (ดูอย่างเดียว กดทำรายการไม่ได้)

## กติกาธุรกิจ (ตามที่ระบบทำอยู่ตอนนี้)

**รอบบิลครึ่งเดือน** — รหัส `YYYY-MM-H1` (1–15) และ `YYYY-MM-H2` (16–สิ้นเดือน) ระบบสร้างรอบให้เองเมื่อถูกอ้างถึง
หน้าจอแสดงเป็นพุทธศักราช เช่น "1–15 ก.ย. 69"

**สินค้า 1 ชิ้น = ร้านเดียวต่อช่วงเวลา** — มอบหมายซ้อนช่วงวันที่ไม่ได้ ย้ายร้านต้องปิดสัญญาเดิมก่อน
**% ส่วนต่างผูกกับสินค้า** และถูกบันทึกติดไปกับยอดขายแต่ละรายการ แก้ % ทีหลังไม่ย้อนไปเปลี่ยนยอดเก่า

**ยอดขายกรอกโดยส่วนกลางเท่านั้น** บันทึกแล้วออกบิลได้เลย ไม่มีขั้นอนุมัติ
**1 ร้าน 1 รอบ = บิลใบเดียว** — กรอกยอดเพิ่มหลังออกบิล ให้เพิ่มเข้าบิลเดิม (ก่อนร้านจ่าย)
วันครบกำหนด = วันจบรอบ + 7 วัน (`paynest.invoiceDueDays`)

**ยอดที่ร้านต้องจ่าย** = ส่วนต่าง + ค่าใช้จ่ายอื่น − ส่วนลด − ยอดยกมา
รอบที่ร้านคืนของมากกว่าขาย (ยอดติดลบ) ไม่มีการโอนคืน — ยกไปหักบิลรอบถัดไปอัตโนมัติ
บิลเลือกสกุลที่ให้ร้านจ่ายได้ (บาท / ดอลลาร์ ตามอัตราที่ตั้งไว้ต่อรอบ)

**การชำระเงิน** — ร้านโอนแล้วแนบสลิป → `รอตรวจ` → ส่วนกลางยืนยัน (ตัดยอดทันที) หรือตีกลับพร้อมเหตุผล
จ่ายทีละงวดได้ · บิลที่มีเงินขยับแล้วแก้ยอดไม่ได้ ต้องยกเลิกแล้วออกใหม่

**ค่าคอมเซล** — ผูกดีลกับสินค้า คิดอัตโนมัติตอนออกบิล (% และ/หรือเหมาต่อรอบ) + เพิ่มค่าคอมอื่นเองได้
**จำนวนเงิน** เก็บเป็นสตางค์ (จำนวนเต็ม) · API รับ/ส่งเป็นบาททศนิยม 2 ตำแหน่ง

**แจ้งเตือน Telegram** (บอทตัวเดียว)

- **กลุ่มของส่วนกลาง** — เลือกรายเรื่องได้ว่าแจ้งทันที / รวมในสรุปรายวัน / ไม่แจ้ง พร้อมช่วงห้ามรบกวน
  เรื่องความปลอดภัยและสำรองข้อมูลไม่สำเร็จแจ้งทันทีเสมอ ปิดไม่ได้
- **แชตส่วนตัวของแต่ละคนในร้าน** — ร้านผูกเองที่หน้าบัญชีของฉัน และเลือกได้ 6 เรื่อง:
  บิลใหม่ · เตือนก่อนครบกำหนด 2 วัน · ทักหลังเลยกำหนด 3/7 วัน · ได้รับเงินแล้ว · สลิปต้องแก้ · ประกาศใหม่

## API

ทุก endpoint อยู่ใต้ `/api/*` และต้องส่ง `Authorization: Bearer <token>` ยกเว้น `/health`, `/api/auth/login*`
และลิงก์ไฟล์สลิปที่ระบบเซ็นให้ ร้านค้าถูกจำกัดให้เห็นเฉพาะข้อมูลของตัวเองที่ฝั่งเซิร์ฟเวอร์เสมอ

รายการ endpoint ที่ถูกต้องที่สุดคือ `app/Config/Routes.php` (ด่านตรวจสิทธิ์เขียนต่อท้ายแต่ละเส้น) →
controller ใน `app/Controllers/Api/` (ตรวจ input ด้วย `V::object([...])` ที่หัวแต่ละเมธอด) → ตรรกะใน `app/Services/`
JSON ที่รับ/ส่งเหมือนระบบเดิมทุกตัวอักษร หน้าเว็บชุดเดิมจึงใช้ได้โดยไม่ต้องแก้
ตัวอย่างการเรียกใช้อยู่ใน `requests.http` (เปิดด้วย REST Client ของ VS Code)

| กลุ่ม | path |
| --- | --- |
| ล็อกอิน · 2FA · ยืนยันรหัส 6 หลัก · Telegram ส่วนตัว · เช็กลิสต์เริ่มต้น | `/api/auth` |
| ร้าน · ผู้ช่วย · ยอดยกมา | `/api/franchises` |
| สินค้า · การมอบหมาย | `/api/products` · `/api/assignments` |

| บิล · ค่าใช้จ่าย/ส่วนลด | `/api/invoices` · `/api/charge-items` |
| แจ้งชำระ · ตรวจสลิป · อัปโหลดไฟล์ | `/api/payments` · `/api/uploads` |
| เซล · ดีล · ค่าคอม | `/api/sales-agents` |

| คู่มือการใช้งานตามบทบาท | `/api/manual` |

## ยังไม่ได้ทำ / ตีความไว้

1. **ยอดขายเป็นยอดรวมต่อสินค้าต่อรอบ** — ไม่ได้เก็บรายบิลหรือรายวัน
2. **ภาษี** (VAT / หัก ณ ที่จ่าย) ยังไม่ได้คิด
3. **ไม่มีไฟล์ PDF ใบเรียกเก็บ/ใบรับเงิน** — เจ้าของระบบตัดสินใจไม่เอา (ใบรับเงินดูบนจอได้)
4. **ไม่มีเครื่องมือย้ายข้อมูลจากระบบเดิม (SQLite)** — ระบบเดิมยังไม่เคยขึ้นใช้งานจริง รุ่นนี้เริ่มจากฐานข้อมูลว่าง
   ถ้าภายหลังมีข้อมูลจริงในระบบเดิมที่ต้องย้าย ค่อยเขียนสคริปต์ (ชื่อตาราง/คอลัมน์ตรงกัน ยกเว้น `app_settings.key` → `name`)
