# ระบบจัดการร้าน (PayNest v2)

ระบบเรียกเก็บส่วนต่างจากยอดขายของร้านในเครือ เก็บเป็น **รอบครึ่งเดือน**
มีหน้าเว็บหลังบ้านสำหรับ 3 บทบาท (ส่วนกลาง · ร้านค้า · เซล) และแจ้งเตือนผ่าน Telegram

รุ่นนี้พอร์ตจากระบบเดิม (Node.js + SQLite) มาเป็น **CodeIgniter 4 + MySQL/MariaDB**
หน้าเว็บ, API, กติกาธุรกิจ และข้อความทุกคำเหมือนเดิม · ชุดทดสอบของระบบเดิมทั้งสองชุดรันกับรุ่นนี้ผ่านครบ
(ยกเว้นคำขอของเจ้าของระบบในรุ่น 2.1.0 — ลิงก์เข้าระบบของร้าน บิลค่าคอมเซล กระเป๋า USD สินค้ากลุ่ม ฯลฯ ดูกติกาด้านล่างและ HANDOVER.md)

- PHP ≥ 8.2 + CodeIgniter 4.7
- MariaDB 10.4+ หรือ MySQL 8.0.19+ (ทดสอบแล้วบน MariaDB 10.4 · MySQL 8.0.16–8.0.18 ใช้ไม่ได้: migration รุ่น 2.1.0 ถอด CHECK ด้วย `DROP CONSTRAINT` ซึ่ง MySQL เพิ่งมีใน 8.0.19 — `app:install` ตรวจรุ่นให้ก่อนเริ่ม)
- หน้าเว็บเป็น vanilla JS + ES modules — **ไม่มีขั้นตอน build** อยู่ใน `public/`
- งานเบื้องหลัง (Telegram, เตือนร้าน, สำรองข้อมูล) ให้ cron เรียกทุกนาที: `php spark schedule:run`
- ตั้งค่าแค่การต่อฐานข้อมูล — กุญแจลับและรหัสแอดมินคนแรกระบบสุ่มให้เอง

## เริ่มใช้งานในเครื่อง

ต้องมี PHP 8.2+ (ส่วนขยาย intl, mbstring, mysqli, curl, gd, openssl, zlib — XAMPP มีครบ) · Composer · MySQL/MariaDB

```bash
composer install
cp env .env                       # แก้ 2 เรื่อง: CI_ENVIRONMENT = development และค่าฐานข้อมูล (database.default.*)
mysql -u root -e "CREATE DATABASE paynest CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
php spark migrate                 # สร้างตาราง
php spark db:seed DemoSeeder      # บัญชี + ข้อมูลตัวอย่าง (เซิร์ฟเวอร์จริงไม่ยอมรัน)
php spark serve                   # เปิด http://localhost:8080
```

ข้อความ Telegram ที่เกิดจากการกดในหน้าเว็บ ระบบส่งให้ทันทีหลังตอบคำขอ
แต่งานตามเวลา (สรุปรายวัน, เตือนร้าน, อ่านข้อความถึงบอทตอนร้านผูก Telegram, สำรองข้อมูล) ไม่รันเองในเครื่อง dev —
อยากลองให้เปิดอีกหน้าต่างแล้วรัน `php spark schedule:work`

บัญชีตัวอย่างหลัง `db:seed` (ใช้ในเครื่อง dev เท่านั้น — เซิร์ฟเวอร์จริงไม่ยอมใช้รหัสพวกนี้):

| บทบาท | ผู้ใช้ | รหัสผ่าน | เข้าทาง |
| --- | --- | --- | --- |
| ส่วนกลาง (super admin) | `superadmin` | `admin1234` | หน้าเข้าสู่ระบบปกติ `/#/login` |
| เจ้าของร้าน | `bkk01` `bkk02` `bkk03` `cnx01` `cnx02` `hdy01` `kkc01` `psk01` `ryg01` `nma01` | `franchise1234` | **ลิงก์ของร้านนั้น** `/#/s/<key>` |
| ผู้ช่วยร้าน | `bkk01-staff` · `bkk02-staff` · `cnx01-staff` | `staff123456` | ลิงก์ของร้านเจ้าของ (เช่น `bkk01-staff` ใช้ลิงก์ของ `bkk01`) |
| เซล | `sale01` … `sale04` (ถือดีลสินค้า) · `sale05` (ไม่มีดีล — ได้แค่ค่าคอมอื่น ๆ) | `sale1234567` | หน้าเข้าสู่ระบบปกติ `/#/login` |

> **ร้านเข้าผ่านลิงก์ของร้านเท่านั้น** (เจ้าของร้านและผู้ช่วย) — ชื่อผู้ใช้กับรหัสถูกแต่ไม่ได้เปิดลิงก์ของร้าน ระบบตอบว่า "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง"
> ลิงก์ของทุกร้านดูได้จากผลลัพธ์ท้าย `php spark db:seed DemoSeeder` (ต่อท้ายที่อยู่เว็บ เช่น `http://localhost:8080/#/s/…`)
> หรือเข้าเป็น `superadmin` → หน้า **ร้านค้า** → **🔗 ลิงก์เข้าระบบ** · เจ้าของร้านเห็นลิงก์ของร้านตัวเองที่หน้า **บัญชีของฉัน**
> เปิดลิงก์ครั้งเดียวแล้วเบราว์เซอร์นั้นจำไว้ (ลองหลายร้านในเครื่องเดียว: เปิดลิงก์ของร้านที่จะเข้าก่อนทุกครั้ง หรือกด "ล้าง" ใต้ฟอร์มเข้าสู่ระบบ)
> ส่วนกลางและเซลไม่ใช้ลิงก์ — เข้าหน้าเข้าสู่ระบบปกติ
> ตัวอย่างสินค้ากลุ่ม: `COFFEE-KIT` (ของร้าน `bkk01` · ดีลของ `sale01`) ประกอบด้วย `GRINDER-P` `BEAN-ARBC` `CUP-PAPER` `LID-DOME` — ดูป้าย "กลุ่ม" / "ประกอบด้วย" ได้ที่หน้าสินค้า ยอดขาย บิลของ `bkk01` และหน้าทำบิลค่าคอมของ `sale01`

> `CI_ENVIRONMENT = development` = โหมดทดสอบ: ไม่บังคับ Google Authenticator · `production` = เซิร์ฟเวอร์จริง: บังคับทุกบัญชีส่วนกลาง (ปิดได้ด้วย `paynest.enforceAdmin2fa = false` ใน `.env` — ไม่แนะนำ)
> ถ้ารัน `php spark app:install` ก่อน `db:seed` แอดมินจะได้รหัสสุ่มแทน `admin1234` — อยู่ในไฟล์ `writable/data/initial-admin-password.txt`

### คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
| --- | --- |
| `php spark serve` | เซิร์ฟเวอร์สำหรับพัฒนา (เครื่องจริงใช้ nginx/Apache + PHP-FPM — ดู DEPLOY.md) |
| `php spark app:install` | ติดตั้ง/อัปเดต: migration + กุญแจลับ + แอดมินคนแรก · รันซ้ำได้ทุกครั้งหลัง `git pull` ไม่ล้างข้อมูล |
| `php spark schedule:run` | งานตั้งเวลา — ให้ cron เรียกทุกนาที |
| `php spark schedule:work` | งานตั้งเวลาแบบรันค้างไว้ (แทน cron · ร้านผูก Telegram เสร็จใน 10 วินาทีแทนไม่เกิน 1 นาที) |
| `php spark app:backup` | สำรองข้อมูลทันที (ปกติระบบทำเองทุกคืน ตี 3 ครึ่ง) |
| `php spark migrate` | รัน migration ที่ค้าง (`app:install` ทำให้อยู่แล้ว) |
| `php spark db:seed DemoSeeder` | ใส่ข้อมูลตัวอย่าง — dev เท่านั้น |
| `php spark app:reset` | ลบตารางทั้งหมด — dev เท่านั้น · มีบิลอยู่ต้องใส่ `--yes-delete-everything` · สำรองให้ก่อนลบเสมอ |
| `php spark 2fa:reset <username>` | ปลด Google Authenticator ของผู้ใช้ (กรณีทำมือถือหาย และไม่มีแอดมินอื่น) |
| `composer test` · `composer test:smoke` · `composer test:pentest` | ทดสอบทั้งหมด / ฟีเจอร์ / เจาะระบบ — ใช้ฐานข้อมูลแยก ไม่แตะข้อมูลจริง (ดู tests/README.md) |
| `node tools/build-icons.mjs` | สร้าง `public/icons.svg` ใหม่ (เฉพาะตอนเพิ่มไอคอน — ดู HANDOVER.md) |

สิทธิ์ของผู้ช่วยเลือกได้ 4 ข้อ: `bills` ดูบิล · `pay` แจ้งชำระ · `reports` ดูรายงาน · `products` ดูสินค้า
ส่วนกลางกด **👁 ดูมุมมองนี้** เพื่อดูระบบแบบที่ร้าน/เซลเห็นได้ (ดูอย่างเดียว กดทำรายการไม่ได้)

## กติกาธุรกิจ (ตามที่ระบบทำอยู่ตอนนี้)

**รอบบิลครึ่งเดือน** — รหัส `YYYY-MM-H1` (1–15) และ `YYYY-MM-H2` (16–สิ้นเดือน) ระบบสร้างรอบให้เองเมื่อถูกอ้างถึง
หน้าจอแสดงเป็นพุทธศักราช เช่น "1–15 ก.ย. 69"

**สินค้า 1 ชิ้น = ร้านเดียวต่อช่วงเวลา** — มอบหมายซ้อนช่วงวันที่ไม่ได้ ย้ายร้านต้องปิดสัญญาเดิมก่อน
**% ส่วนต่างผูกกับสินค้า** และถูกบันทึกติดไปกับยอดขายแต่ละรายการ แก้ % ทีหลังไม่ย้อนไปเปลี่ยนยอดเก่า
**สินค้าลบไม่ได้ — ปิดใช้งาน / เปิดใช้งานแทน** ปิดแล้วร้านไม่เห็น กรอกยอดใหม่ไม่ได้ และผูกดีลใหม่ไม่ได้
ยอดที่บันทึกไว้แล้วยังออกบิลได้ · สัญญากับร้านและดีลของเซลค้างไว้ตามเดิม (เปิดใช้งานอีกครั้งแล้วใช้ต่อได้ทันที)
ร้านที่มีแต่สินค้าที่ปิดใช้งานไม่ถูกนับเป็น "ยังไม่กรอกยอด"

**สินค้ากลุ่ม (ชุด)** — สินค้ากลุ่ม**คือสินค้าหนึ่งชิ้น** (รหัส ชื่อ % ส่วนต่าง สถานะ มอบหมายให้ร้านเดียว ยอดขาย ดีลเซล บิล — ทุกอย่างเหมือนสินค้าปกติ)
ที่ติ๊กไว้ว่าในชุดมีสินค้าย่อยอะไรบ้าง · สร้าง/แก้ได้เฉพาะส่วนกลาง (หน้าสินค้า → สวิตช์ "สินค้ากลุ่ม (ชุด)")
- กรอกยอดขายเป็น**ยอดรวมของทั้งชุดก้อนเดียว** · บิลคิด **% ของกลุ่มเป็นบรรทัดเดียว** · สินค้าย่อยเป็นข้อมูลอย่างเดียว ไม่มียอดแยก ไม่ถูกคิดเงินซ้ำ
  (ใต้บรรทัดบิลเขียน "ประกอบด้วย: รหัส, รหัส, …" ให้ร้านรู้ว่าในชุดมีอะไร)
- สินค้าย่อย = สินค้าที่มีอยู่แล้ว อย่างน้อย 1 สูงสุด 100 รายการ · ใส่ตัวเองหรือสินค้ากลุ่มอื่นไม่ได้ (**ไม่มีกลุ่มซ้อนกลุ่ม**) · ติ๊กซ้ำนับครั้งเดียว
  · สินค้าชิ้นเดียวอยู่ได้หลายกลุ่ม · สินค้าย่อยไม่ต้องมอบหมายให้ร้านเดียวกับกลุ่ม (เป็นแค่ข้อมูล)
- สินค้าที่ปิดใช้งานแล้ว**เพิ่มเข้ากลุ่มใหม่ไม่ได้** (ที่อยู่ในกลุ่มตั้งแต่ก่อนปิดยังอยู่ได้) · สินค้าที่อยู่ในกลุ่มใดอยู่**เปลี่ยนเป็นสินค้ากลุ่มไม่ได้** (เอาออกจากกลุ่มก่อน)
  · ปิดสวิตช์กลุ่ม = กลับเป็นสินค้าเดี่ยว รายการย่อยถูกล้าง · แก้รายการย่อยทุกครั้งขึ้นในประวัติ (เพิ่ม/เอาออกอะไร)
- **บิลจำรายการย่อย ณ ตอนออกบิล** — แก้รายการย่อยทีหลัง บิลเก่ายังโชว์ของเดิม · ยกเลิกบิลแล้วออกใหม่ = ใช้รายการปัจจุบัน
- ค่าคอมเซล: ผูกดีลกับสินค้ากลุ่มได้เหมือนสินค้าปกติ — % คิดจากยอดขายเต็มของทั้งชุด เป็นรายการเดียวในบิลค่าคอม ·
  **ดีลของสินค้าย่อยไม่ได้ค่าคอมจากยอดที่ขายเป็นชุด** (ยอดของชุดบันทึกที่สินค้ากลุ่ม) — ถ้าเซลควรได้จากชุดด้วย ให้ผูกดีลกับสินค้ากลุ่ม

**ยอดขายกรอกโดยส่วนกลางเท่านั้น** บันทึกแล้วออกบิลได้เลย ไม่มีขั้นอนุมัติ
**1 ร้าน 1 รอบ = บิลใบเดียว** — กรอกยอดเพิ่มหลังออกบิล ให้เพิ่มเข้าบิลเดิม (ก่อนร้านจ่าย)
วันครบกำหนด = วันจบรอบ + 7 วัน (`paynest.invoiceDueDays`)

**ยอดที่ร้านต้องจ่าย** = ส่วนต่าง + ค่าใช้จ่ายอื่น − ส่วนลด − ยอดยกมา
รอบที่ร้านคืนของมากกว่าขาย (ยอดติดลบ) ไม่มีการโอนคืน — ยกไปหักบิลรอบถัดไปอัตโนมัติ
บิลเลือกสกุลที่ให้ร้านจ่ายได้ (บาท / ดอลลาร์ ตามอัตราที่ตั้งไว้ต่อรอบ)

**วิธีคิดยอดรายสินค้าในบิล** — ตอนออกบิลทีละร้าน ติ๊กเลือกสินค้า แล้วแต่ละสินค้าเลือกได้
`คิดตาม %` (ตั้งต้นที่ % ของสินค้า แก้ได้) หรือ `กรอกยอดเอง` (พิมพ์ส่วนต่างที่เรียกเก็บ ต้องอยู่ระหว่าง 0 ถึงยอดเงินเต็ม)
แก้ทีหลังได้ทีละบรรทัดเฉพาะบิลที่ยังแก้ได้ (ยังไม่มีเงินเข้า ไม่มีสลิปรอตรวจ) — ค่าใช้จ่าย/ส่วนลดที่คิดเป็น % คิดใหม่ตาม
ร้านเห็นบรรทัดที่กรอกเองเป็น "กำหนดยอด" · ออกหลายร้านพร้อมกันใช้วิธีที่บันทึกไว้ของแต่ละรายการ (ปกติคือ %)
บันทึกยอดขายของรายการนั้นใหม่ (หลังยกเลิกบิล) = กลับไปคิดตาม %
ออกบิลร้าน**ไม่สร้างค่าคอมเซล**แล้ว — ค่าคอมเซลทำเป็น "บิลค่าคอม" แยกทีหลัง (ดูหัวข้อค่าคอมเซลด้านล่าง)

**รูปประกอบบิล** — แนบรูป/PDF ได้สูงสุด 10 ไฟล์ต่อบิล ตอนออกบิลหรือทีหลัง (แม้ร้านจ่ายแล้ว — ไม่แตะยอดเงิน)
ร้านเห็นเฉพาะของบิลตัวเอง ผ่านลิงก์ที่เซ็นแล้ว · ลบ = ซ่อนจากบิล ไฟล์ไม่ถูกลบจากเครื่อง (เป็นหลักฐาน) · บิลที่ยกเลิกแล้วแนบ/ลบไม่ได้

**การชำระเงิน** — ร้านโอนแล้วแนบสลิป → `รอตรวจ` → ส่วนกลางยืนยัน (ตัดยอดทันที) หรือตีกลับพร้อมเหตุผล
จ่ายทีละงวดได้ · บิลที่มีเงินขยับแล้วแก้ยอดไม่ได้ ต้องยกเลิกแล้วออกใหม่

**ตรวจเลขบัญชีก่อนโอน (กติกาของเจ้าของระบบ)** — ทุกข้อความ Telegram ที่เกี่ยวกับบิล (บิลออก เตือนก่อน/หลังครบกำหนด แจ้งบัญชี)
มีธนาคาร เลขที่บัญชี ชื่อบัญชี (กระเป๋า USD: เครือข่าย + ที่อยู่กระเป๋า) และคำเตือน: ตรวจให้ตรงกับในระบบทุกครั้ง · ไม่ตรง **ห้ามโอนเด็ดขาด** ·
โอนผิดบัญชีหรือโอนเข้าบัญชีที่ไม่ตรงกับที่แจ้งทาง Telegram ทางเราไม่รับผิดชอบทุกกรณี
- หน้าเว็บของร้านขึ้นคำเตือนเดียวกันที่กล่องบัญชี และบอกสถานะของบิล: ตรงกับ Telegram / ยังไม่เคยส่ง / **ไม่ตรง (ห้ามโอน)**
- แจ้งชำระต้องติ๊กยืนยันว่าตรวจเลขบัญชีแล้ว (บิลที่ยังไม่ได้เลขทาง Telegram = ยืนยันกับทางเราโดยตรง) — เก็บเป็นหลักฐานพร้อมบัญชีที่บิลชี้ตอนแจ้ง
  บัญชีของบิลเปลี่ยนระหว่างที่ร้านเปิดฟอร์มค้าง = เซิร์ฟเวอร์ตอบ 409 ให้ร้านตรวจใหม่
- **เปลี่ยนบัญชีรับเงิน** (ตัวบัญชี หรือบัญชีของบิลใบใดใบหนึ่ง) ต้องใส่รหัส 6 หลัก และแจ้งกลุ่ม Telegram ส่วนกลางทันที (ปิดไม่ได้)
  **ระบบไม่ส่งเลขบัญชีใหม่ให้ร้านเอง** — ส่วนกลางตรวจแล้วกด "📨 ส่งเลขบัญชีให้ร้าน" (ที่บิล หรือทุกบิลค้างของบัญชีนั้นที่หน้าบัญชีรับเงิน) ซึ่งต้องใส่รหัส 6 หลักเช่นกัน
  ระหว่างนั้นร้านเห็นว่าไม่ตรงกับ Telegram และจะไม่โอน (ถ้าระบบส่งเอง คนที่เจาะบัญชีแอดมินได้ก็สั่งให้ระบบบอกร้านโอนเข้าบัญชีตัวเองได้)

**บัญชีรับเงิน USD = กระเป๋าคริปโต** — บัญชีบาทเป็นบัญชีธนาคารไทย (ธนาคาร ชื่อบัญชี เลขที่บัญชี สาขา) ·
บัญชี USD กรอกแค่ **เครือข่าย (chain)** เช่น TRC20 · **ที่อยู่กระเป๋า** (คัดลอกมาทั้งชุด ห้ามมีช่องว่าง) · รูป QR (ไม่บังคับ)
- เก็บในตารางเดิม: `account_number` = ที่อยู่กระเป๋า (ยาวได้ 128 ตัว) · `chain` = เครือข่าย · `bank_name` = เครือข่ายด้วย (ทุกที่ที่พิมพ์ชื่อธนาคารจะเห็นเครือข่ายแทน) · ชื่อบัญชีว่าง
- ป้ายบัญชี `USD · TRC20 · <ที่อยู่>` · ข้อความ Telegram ของบิล USD บอกเครือข่ายกับที่อยู่ + "โอนผิดเครือข่าย (chain) เงินจะสูญหายและกู้คืนไม่ได้"
- หน้าชำระเงินของร้านโชว์เครือข่ายตัวใหญ่ ที่อยู่เต็มทุกตัวอักษรพร้อมปุ่มคัดลอก และคำเตือนเรื่องเครือข่าย · แก้เครือข่ายนับเป็นการเปลี่ยนปลายทางเงิน (รหัส 6 หลัก + แจ้งกลุ่ม)

**ค่าคอมเซล** — จ่ายเป็น **บิลค่าคอม** ที่ส่วนกลางทำเองเป็นครั้ง ๆ (แต่ละรอบจ่ายไม่เหมือนกัน) — ออกบิลร้านไม่สร้างค่าคอมอัตโนมัติ
1. **ดีล** = เซลถือสินค้านั้น + % ของยอดขายเต็ม และ/หรือเหมาต่อรอบ — **ไม่มีวันที่ให้เลือก** (เริ่มวันที่ผูก · "ปิดดีล" กดเดียว) · สินค้าหนึ่งชิ้นมีดีลเปิดได้คนเดียว
   **% คิดจากยอดขายเต็มของร้านเสมอ** (ก่อนหักส่วนต่าง — ไม่มีให้เลือกฐานแล้ว) · **ดีลไม่บังคับ** เซลที่ได้แค่ "ค่าคอมอื่น ๆ" ไม่ต้องผูกดีล
   **ดีลที่ผูกแล้วแก้ได้** (% / เหมาต่อรอบ / หมายเหตุ) ตรงที่เห็นดีล — "ตั้งค่าคอม" ของแถวเซล (ดีลเดิมขึ้นก่อนเป็นแถวที่แก้/ปิดได้) · "รายละเอียด" ของเซล · แท็บ "ดีล สินค้า ↔ เซล"
   ตัวเลขใหม่เป็นค่าตั้งต้นของ**บิลค่าคอมที่ทำหลังจากนั้น** — บิลค่าคอมที่ทำไปแล้วไม่เปลี่ยน (รายการในบิลเก็บตัวเลขตอนทำบิลไว้)
2. **🧾 ทำบิลค่าคอม** — ติ๊กรายการจากบิลร้านที่ออกแล้ว (ไม่ต้องรอร้านจ่าย) เฉพาะสินค้าที่เซลคนนั้นถือดีล · แต่ละรายการเลือก
   `% ของยอดเต็ม` (ตั้งต้นตาม % ในดีล แก้ได้) หรือ `กรอกเอง` · เหมาต่อรอบติ๊กแยก (ครั้งเดียวต่อ เซล × ร้าน × รอบ) ·
   `ค่าคอมอื่น ๆ` พิมพ์รายการ + จำนวนเงิน **ไม่ต้องเลือกรอบ** (ติดลบได้ = หักคืน) · ยอดรวมต้องมากกว่า 0
3. รายการจากบิลร้านหนึ่งบรรทัดจ่ายเป็นค่าคอมได้ครั้งเดียว (ฐานข้อมูลกันซ้ำ) · **ยกเลิก**บิลค่าคอมที่ยังไม่จ่าย (ใส่เหตุผล) = รายการกลับมาติ๊กได้อีก ·
   จ่ายแล้วยกเลิกไม่ได้ (จ่ายเกิน ให้ใส่ค่าคอมอื่น ๆ ติดลบในบิลถัดไป)
4. บิลร้านถูกยกเลิก → รายการของบิลนั้นถูกถอดจากบิลค่าคอมที่ยังไม่จ่าย (ไม่เหลือรายการ = บิลค่าคอมถูกยกเลิกเอง) · บิลค่าคอมที่จ่ายแล้วไม่ถูกแตะ
- ค่าคอมแบบเดิม (ต่อบิลร้าน / "ค่าคอมอื่น ๆ" รายรอบ) ที่มีอยู่แล้วยังดู จ่าย และยกเลิกได้ตามปกติ

**จำนวนเงิน** เก็บเป็นสตางค์ (จำนวนเต็ม) · API รับ/ส่งเป็นบาททศนิยม 2 ตำแหน่ง

**เข้าระบบของร้าน = ลิงก์ลับของแต่ละร้าน** — ผู้ใช้ของร้าน (เจ้าของ + ผู้ช่วย) ต้องมี**ทั้งรหัสผ่านและลิงก์ของร้าน** `/#/s/<key>`
(ส่วนกลางและเซลเข้าหน้าปกติ) · ไม่มีลิงก์ / ลิงก์ของร้านอื่น / ลิงก์เก่า = ตอบเหมือนรหัสผิดทุกตัวอักษร (เดารหัสแล้วรู้ไม่ได้ว่าถูก) และนับเป็นการเข้าผิด
- เปิดลิงก์ครั้งเดียว เบราว์เซอร์นั้นจำไว้ (ลิงก์หายจากแถบที่อยู่ทันที) · ใต้ฟอร์มเข้าสู่ระบบบอกว่าจำไว้แล้วไหม และกด "ล้าง" ได้ (เครื่องใช้ร่วม)
- ส่วนกลางดู/คัดลอกลิงก์ได้ที่หน้าร้านค้า · เจ้าของร้านเห็นลิงก์ของร้านตัวเองที่หน้าบัญชีของฉัน (ไว้ส่งให้ผู้ช่วย) · ผู้ช่วยดูไม่ได้
- **สร้างลิงก์ใหม่** (ส่วนกลาง + รหัส 6 หลัก) = ลิงก์เดิมใช้ไม่ได้ทันที ทุกคนของร้านถูกออกจากระบบ และแจ้งกลุ่ม Telegram ส่วนกลาง (ปิดไม่ได้) — ใช้เมื่อสงสัยว่าลิงก์หลุด

**ส่งข้อมูลเข้าระบบให้ลูกค้า — "📋 คัดลอกทั้งชุด"** ลิงก์ + ชื่อผู้ใช้ + รหัสผ่านเป็นข้อความก้อนเดียว วางในแชตได้เลย
- รหัสผ่านเก็บแบบเข้ารหัสทางเดียว **ดูย้อนหลังไม่ได้** — ชุดที่มีรหัสผ่านจึงได้เฉพาะตอนสร้างบัญชี หรือตอนกด **"🔑 ตั้งรหัสใหม่ + คัดลอก"**
  (สุ่มรหัสให้ · เจ้าของบัญชีถูกออกจากระบบทุกเครื่อง · **เข้าครั้งแรกระบบบังคับตั้งรหัสใหม่ของตัวเอง**) · นอกนั้น "📋 คัดลอกข้อมูลเข้าระบบ" ได้ลิงก์ + ชื่อผู้ใช้
- มีที่หน้าร้านค้า (ส่วนกลาง → เจ้าของร้านและผู้ช่วย) · หน้าบัญชีของฉัน (เจ้าของร้าน → ผู้ช่วย) · หน้าเซล (ส่วนกลาง → เซล · ลิงก์ = หน้าเข้าสู่ระบบปกติ)

**แจ้งเตือน Telegram** (บอทตัวเดียว)

- **กลุ่มของส่วนกลาง** — เลือกรายเรื่องได้ว่าแจ้งทันที / รวมในสรุปรายวัน / ไม่แจ้ง พร้อมช่วงห้ามรบกวน
  เรื่องความปลอดภัยและสำรองข้อมูลไม่สำเร็จแจ้งทันทีเสมอ ปิดไม่ได้
- **แชตส่วนตัวของแต่ละคนในร้าน** — ร้านผูกเองที่หน้าบัญชีของฉัน มี 7 เรื่อง:
  บิลใหม่ · แจ้ง/เปลี่ยนบัญชีสำหรับโอนของบิล · เตือนก่อนครบกำหนด 2 วัน · ทักหลังเลยกำหนด 3/7 วัน · ได้รับเงินแล้ว · สลิปต้องแก้ · ประกาศใหม่
  สองเรื่องแรก**ปิดไม่ได้** (มีเลขบัญชีที่ร้านต้องใช้ตรวจก่อนโอน) · ที่เหลือเลือกเปิด/ปิดได้เอง

## API

ทุก endpoint อยู่ใต้ `/api/*` และต้องส่ง `Authorization: Bearer <token>` ยกเว้น `/health`, `/api/auth/login*`
และลิงก์ไฟล์สลิปที่ระบบเซ็นให้ ร้านค้าถูกจำกัดให้เห็นเฉพาะข้อมูลของตัวเองที่ฝั่งเซิร์ฟเวอร์เสมอ

รายการ endpoint ที่ถูกต้องที่สุดคือ `app/Config/Routes.php` (ด่านตรวจสิทธิ์เขียนต่อท้ายแต่ละเส้น) →
controller ใน `app/Controllers/Api/` (ตรวจ input ด้วย `V::object([...])` ที่หัวแต่ละเมธอด) → ตรรกะใน `app/Services/`
JSON ที่รับ/ส่งเหมือนระบบเดิมทุกตัวอักษร หน้าเว็บชุดเดิมจึงใช้ได้โดยไม่ต้องแก้
ตัวอย่างการเรียกใช้อยู่ใน `requests.http` (เปิดด้วย REST Client ของ VS Code)

## ยังไม่ได้ทำ / ตีความไว้

1. **ยอดขายเป็นยอดรวมต่อสินค้าต่อรอบ** — ไม่ได้เก็บรายบิลหรือรายวัน
2. **ภาษี** (VAT / หัก ณ ที่จ่าย) ยังไม่ได้คิด
3. **ไม่มีไฟล์ PDF ใบเรียกเก็บ/ใบรับเงิน** — เจ้าของระบบตัดสินใจไม่เอา (ใบรับเงินดูบนจอได้)
4. **ไม่มีเครื่องมือย้ายข้อมูลจากระบบเดิม (SQLite)** — ระบบเดิมยังไม่เคยขึ้นใช้งานจริง รุ่นนี้เริ่มจากฐานข้อมูลว่าง
   ถ้าภายหลังมีข้อมูลจริงในระบบเดิมที่ต้องย้าย ค่อยเขียนสคริปต์ (ชื่อตาราง/คอลัมน์ตรงกัน ยกเว้น `app_settings.key` → `name`)
