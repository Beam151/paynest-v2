# ชุดทดสอบ

| ไฟล์ | ทดสอบอะไร |
| --- | --- |
| `e2e/smoke.mjs` | ทุกฟีเจอร์ผ่าน HTTP จริง 444 ข้อ — บิล ชำระเงิน ค่าคอม สิทธิ์ 2FA Telegram แจ้งเตือน สำรองข้อมูล ฯลฯ |
| `e2e/pentest.mjs` | ลองโจมตีจริง 93 แบบ — ทุกข้อ "ผ่าน" = ระบบกันได้ |
| `e2e/lib/harness.mjs` | ตัวตั้งฉาก: ฐานข้อมูลเทสต์ใหม่ → `app:install` → เปิด `php -S` บนพอร์ตสุ่ม + Telegram จำลอง |
| `unit/` | PHPUnit (`composer test:unit`) |

ทั้งสองชุดพอร์ตมาจากชุดทดสอบของระบบเดิม (Node) แบบคำต่อคำ — เปลี่ยนเฉพาะส่วนที่เดิมเรียกโค้ดภายในโดยตรง
(อ่านฐานข้อมูล / เรียกงานตั้งเวลา) ให้ผ่าน `php spark e2e:sql` / `e2e:call` แทน · เงื่อนไขที่เช็กยังเป็นข้อเดิม

## รัน

```bash
composer test            # smoke แล้วต่อด้วย pentest
composer test:smoke
composer test:pentest
```

ต้องมี **Node ≥ 18** (ไม่ต้อง `npm install`) และ **MySQL/MariaDB** ที่ผู้ใช้สร้าง/ลบฐานข้อมูลได้
ทั้งสองชุดใช้เวลารวมราว 1–3 นาที (smoke ต้องรอรหัส 6 หลักช่วงใหม่หลายครั้งเหมือนคนใช้จริง)

ตั้งค่าผ่านตัวแปรสภาพแวดล้อม (ไม่ตั้ง = ค่าในวงเล็บ):

| ตัวแปร | ใช้ทำอะไร |
| --- | --- |
| `E2E_DB_HOST` / `E2E_DB_PORT` / `E2E_DB_USER` / `E2E_DB_PASS` | ต่อฐานข้อมูล (`127.0.0.1` / `3306` / `root` / ว่าง) |
| `E2E_PHP` | คำสั่ง php (`php`) |
| `E2E_MYSQL_CLI` | โปรแกรม `mysql` — ตั้งแล้ว smoke จะลองกู้ไฟล์สำรองเข้าฐานข้อมูลชั่วคราวจริง (ไม่ตั้ง = นับแถวในไฟล์แทน) |
| `SMOKE_DB` / `PENTEST_DB` | ชื่อฐานข้อมูลของแต่ละชุด (`paynest_e2e_smoke` / `paynest_e2e_pentest`) |

ตัวอย่างบน Windows + XAMPP: `E2E_MYSQL_CLI=D:/xampp/mysql/bin/mysql.exe composer test`

## ปลอดภัยกับข้อมูลจริง

- ฐานข้อมูลของเทสต์ถูก **ลบแล้วสร้างใหม่ทุกครั้ง** — ชื่อต้องมีคำว่า `e2e` หรือ `test` (ตัวตั้งฉากไม่ยอมแตะชื่ออื่น)
  ชุดทดสอบใช้: `paynest_e2e_smoke` · `paynest_e2e_pentest` · `paynest_e2e_firstboot` · `paynest_e2e_seedprod` · `paynest_e2e_restore`
- ไฟล์ (กุญแจลับ, สลิป, ไฟล์สำรอง) อยู่ในโฟลเดอร์ temp ของเครื่องแล้วลบทิ้งตอนจบ — ไม่แตะ `writable/data/`
- ค่าในเครื่องที่ชุดทดสอบทับให้: ฐานข้อมูล (`PAYNEST_DB_*`) · `CI_ENVIRONMENT` · โฟลเดอร์ข้อมูล · กุญแจลับ
  ส่วน `paynest.*` อื่น ๆ ใน `.env` ของเครื่องยังมีผล — ถ้าเทสต์พังแปลก ๆ ลองดูว่า `.env` ตั้งอะไรแปลกไว้ไหม
- smoke รันแบบ production (บังคับ 2FA) · pentest รันแบบ development (ค่าที่ลืมเปลี่ยนตอน deploy แล้วอันตรายที่สุด)

## เพิ่มเทสต์

ต่อท้ายใน `e2e/smoke.mjs` เป็น `section('ชื่อ')` + `check('สิ่งที่ต้องจริง', เงื่อนไข, ข้อมูลตอนพัง)`

- ยิง API: `await api('POST', '/api/...', { token, body })` → `{ status, body }` (แอดมินใส่รหัส 6 หลักให้เองเมื่อเส้นทางต้องใช้)
- อ่าน/แก้ฐานข้อมูลตรง ๆ: `db.prepare(sql).get(...)` / `.all(...)` / `.run(...)` — SQL แบบ MySQL
- เรียกงานเบื้องหลัง: `call('runDueReminders', { now: thaiWall(date) })` — งานใหม่ต้องเพิ่มใน `app/Commands/E2eCall.php`
- ข้อความ Telegram ที่ระบบส่ง: `telegram.messages` (Telegram จำลอง — ไม่ส่งออกจริง)
- `db.prepare` / `call` เรียก `php spark` ครั้งละโปรเซส (ราว 0.3 วินาที) — ใช้เท่าที่จำเป็น
- **section สุดท้ายต้องเป็นเรื่องใส่รหัสผิดจนล็อก** (มันล็อกการยืนยันตัวตนไป 15 นาที)

ข้อที่เช็กสิทธิ์ไฟล์แบบ POSIX (600/700) ข้ามไปเมื่อรันบน Windows — เครื่องจริงเป็น Linux ตรวจครบ
